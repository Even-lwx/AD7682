# 自动干扰诊断（第 4 版）

烧录后每次上电自动执行一次，先测 IN2，再测 IN1；每路 15 阶段，
每阶段 96 组、每组 5 次原始转换。不要求发送命令。
请保持传感器和其他通道接线不变，串口软件在复位前开始录制。
预计约 1～2 分钟完成，实际时间包含阶段结束后的缓冲数据发送。

## 阶段

| 阶段 | 条件 |
| --- | --- |
| 0 | 基准：SPI 2 MHz，CNV 拉低后等待 500 us，组周期 20 ms |
| 1 | 关闭 SysTick 中断 |
| 2 | 关闭 TIM14 中断 |
| 3 | 同时关闭以上两种中断 |
| 4 | SPI 1 MHz |
| 5 | SPI 4 MHz |
| 6 | 等待 100 us |
| 7 | 等待 1000 us |
| 8 | 组周期 17/23 ms 交替 |
| 9 | 重复基准 |
| 10 | 等待 3000 us，五个点跨约 12 ms，观察脉冲持续时间 |
| 11 | 组间空闲采用 WFI 睡眠，SysTick 保持开启 |
| 12 | 组间空闲持续整数运算 |
| 13 | 组周期 10 ms（100 Hz），其余沿用基准 |
| 14 | 再次重复基准，检查测试期间基线漂移 |

未特别列出的参数与基准一致。11/12 只比较组间活动，采样前最后
2 ms 均轮询等待；这不是“转换期间完全没有 CPU 活动”的试验。
10 的 3000 us 是 CNV 拉低后的等待，并非增加 CNV 高电平转换时间。
本轮不改变外部参考源配置，不启用滤波掩盖测试原始值。

## FireWater 输出

每行固定 12 个数值，前缀 ADC:。CSV 的 I0 是标识：

- 数据行 I0 = 通道 × 100 + 阶段。例如 110 是 IN1 的阶段 10，
  210 是 IN2 的阶段 10。
- I1：本阶段内第一点 CNV 时间，单位 us。
- I2～I6：五个原始 ADC 码。
- I7～I10：第 2～5 点相对第一点的 CNV 时间，单位 us。
- I11：状态，0 正常，1 通信错误，2 超时；另加 256 表示调度迟到，
  512 表示时间差超出字段范围。错误行不应被统计成真实信号。

事件行也有 12 个值：

- 990：版本 4、15 阶段、每阶段 96 组等启动参数。
- 991：本阶段标识、等待 us、SPI Hz、SysTick关闭、TIM14关闭、
  首个组周期 us、SPI初始化状态、预热读取状态、组间活动模式
  （0轮询、1睡眠、2整数运算），末尾两个值为0。
  阶段8后续周期交替变化，以数据时间戳为准。
- 992：切换到 IN1。
- 999：测试完成。

捕获期间不打印、不读取其他传感器、不访问 W25Q128；接收中断仍开启。
其他传感器已正常初始化，但这段测试数据不保存为正常历史记录。

## 自动恢复正常工作

999 后恢复 SPI 2 MHz、等待100 us、四路每路100 Hz，重新填充各路
100点中值＋25点平均窗口（约1秒）。正常串口 I7～I10 继续输出两位
小数，W25Q128 保存带0.01码精度的滤波结果；正常记录间隔从测试完成
时重新计时，不补写测试期间的历史数据。记录写入优先于实时串口输出。

诊断缓冲和滤波缓冲共用RAM，因此两种模式不能同时运行；恢复时清空
滤波状态和待写标志，防止原始诊断数据被当成滤波值写入历史记录。
后续仍可用 adcdiag 0..3 手动测试指定通道，但正常使用不需要发送它。
