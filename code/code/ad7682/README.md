# AD7682 驱动说明

本驱动对应工程原理图中的 AD7682（U5）。

## 原理图连接

- SPI1 SCK：PA1（SCK）
- SPI1 SDO：PA6（SDO）
- SPI1 DIN：PA7（DIN）
- 转换启动 CNV：PA5

原理图文件为 `pcb/AD7682-Ver1.0/Sheet1.SchDoc`。AD7682 的 CNV、DIN、SCK、SDO
分别为芯片 11、12、13、14 脚；IN0、IN1、IN2、IN3 分别为 16、18、7、9 脚；COM
接地。VDD/VIO 为 3 V，当前固件选择外部 REF 参考源（REF[5:3]=110），
关闭内部参考缓冲器和内部参考输出。REF 引脚由外部 `2V5_SENSOR`（REF3025）
通过 0 Ω 连接，并按外部参考电路进行去耦。

## 配置和通信协议

依据 `doc/C398823_模数转换芯片ADC_AD7682BCPZ_规格书_WJ214604.PDF` Rev. B
第 7、19、21、23～25、28 页。CFG 是 14 位配置字，并非 I2C 那种带地址的寄存器。
基础配置值为 `0x3C71`，通道选择值为 `channel << 7`：

| 字段 | 配置值 | 含义 |
| --- | --- | --- |
| CFG[13] | 1 | 更新配置 |
| INCC[12:10] | 111 | 相对于 GND 的单端单极性输入 |
| INx[9:7] | 000～011 | 选择 IN0～IN3 |
| BW[6] | 1 | 全带宽 |
| REF[5:3] | 110 | 使用外部 REF，关闭内部参考缓冲器和内部参考输出 |
| SEQ[2:1] | 00 | 关闭通道序列器，使用显式通道选择 |
| RB[0] | 1 | 关闭配置回读 |

SPI1 使用模式 0、MSB 先传、8 位数据、2 MHz 时钟（64 MHz ÷ 32）。每次事务先保持
SCK/DIN 安静 10 µs，再将 CNV 拉高并等待转换完成；拉低 CNV 后等待 500 µs 采集
保持时间，然后交换 2 字节。
通道切换时仅第一次事务按 MSB 对齐发送 `CFG << 2`；配置更新完成后 DIN 保持全零，
避免不必要的数字边沿。由于 RB=1，接收的 16 位就是转换结果，后续不再发送 CFG
回读时钟。每次事务结束后 CNV 保持低电平，确保下一次调用产生有效上升沿。

当前配置在 CNV 拉低后额外等待 500 µs；等待由 TIM2 的 1 MHz 自由计数器实现，
而不是依赖循环次数。中断可能让实际等待略长，诊断时间戳记录实际转换间隔。
对于 100 Ω + 100 pF 的输入网络，
该时间仍远大于 RC 建立时间和数据手册规定的 1.8 µs 最小采集时间。CNV 上升沿至
转换结束的关键段，以及 CNV 上升沿前 10 µs 安静窗口，暂时屏蔽 SysTick、TIM14 和
UART 中断，避免数字电流与 ADC 转换瞬间重合。CFG 具有一拍
流水线延迟，因此每次切换通道后先执行两次丢弃转换，再连续读取 5 个有效结果。
五个有效结果按排序后取第 3 个样本作为该通道输出，抑制单次或少量尖峰，同时保留
多次采样带来的精度。

## 应用行为

- 上电初始化最多重试 3 次，并输出 `AD7682 INIT OK` 或 `AD7682 INIT ERROR`。
- 每轮按 IN0、IN1、IN2、IN3 顺序扫描四个通道；每个通道为“2 次丢弃转换 + 5 次
  有效转换”，实时串口和历史记录输出五次采样的中值结果。
- 单次有效转换失败时，本轮四个 ADC 字段统一输出 `65535`，避免把未完成扫描的
  部分结果误当成同一时刻的数据。
- SPI 通信失败时 ADC 字段输出 `65535`，其他传感器采样、命令处理和日志导出继续运行；
  通信恢复后自动恢复正常采样。
- `setting` 状态下仍继续采样和按周期记录，只暂停实时数据行输出。
- 电压换算公式为 `code × measured_REF / 65536`，当前参考电压标称值为 2.5 V。

正常采集由 TIM14 每 20 ms 置位请求，耗时操作在主循环运行。若采集和发送超过周期，
请求会合并，因此实际串口频率不能仅按 50 Hz 理论值计算。
ADC 延时与超时统一由 TIM2 计时，不依赖 SysTick；SPI 异常会有限超时并复位 SPI1。

## 自动诊断第二版（2026-10-20）

上电初始化后自动依次测 IN2 和 IN1，每通道十组，每组 96 行、每行五个未经滤波的原始值。
保持本次测试接线不变；所有传感器正常初始化，两个 LPS22HH 保持原有连续采样配置。
诊断期间暂不访问 I2C、输出常规传感器数据或写历史记录。采集窗口内 UART 不发送，
各组数据先存在 RAM，组结束、恢复中断后再集中发送。约一分钟完成；实际还包含初始化时间。
结束后恢复 2 MHz SPI、500 us 等待和原有四通道采集/日志流程。诊断值不写入 Flash。

TIM2 是不产生中断的 32 位 1 MHz 计时器；所有组都由它调度，关闭 TIM14 或 SysTick
中断不会改变目标触发周期。两种中断只是关闭请求，计数器仍在运行；组结束补偿丢失的
HAL/记录毫秒时间。UART RX 保持开启，测试窗口内收到的命令在整轮测试结束后处理。

| 阶段号 | 条件（其他配置同基准） |
| --- | --- |
| 0 | 基准：SPI 2 MHz，CNV 下降沿后等待 500 us，每 20 ms 一组 |
| 1 | 关闭 SysTick 中断 |
| 2 | 关闭 TIM14 中断 |
| 3 | 同时关闭 SysTick、TIM14 中断 |
| 4 | SPI 改为 1 MHz |
| 5 | SPI 改为 4 MHz |
| 6 | CNV 下降沿后等待改为 100 us |
| 7 | CNV 下降沿后等待改为 1000 us |
| 8 | 组触发间隔 17/23 ms 交替，平均 20 ms |
| 9 | 再测一次基准，检查时间漂移 |

所有诊断帧均为 FireWater `ADC:` 前缀、12 个数字字段、CRLF 结尾。
VOFA 中 I0 为标识，I2～I6 仍是五个原始值；不要用串口接收速度反推采样速度。

| 字段 | 数据行含义 |
| --- | --- |
| I0 | `100 × 通道号 + 阶段号`：IN2 为 200～209，IN1 为 100～109 |
| I1 | 本组第一次有效转换相对于本阶段起点的时间，单位 us |
| I2～I6 | 五次原始码，无均值、中位数或尖峰剔除 |
| I7～I10 | 第 2～5 次转换相对于第 1 次的时间差，单位 us |
| I11 | 状态：低字节 0=成功、1=错误、2=超时；256=调度迟到/超期；512=偏移超范围 |

每次转换时间由读取 TIM2 后立即拉高 CNV 得到，分辨率为 1 us，存在短小固定访问延迟，
不是示波器测量值。第 j 次转换的阶段内时间为 I1 加对应偏移（第 1 次偏移为 0）。
不同阶段时间起点独立，不能把 I1 跨阶段直接相减。65535 同时可能是合法满量程码，
因此通信是否失败要看 I11，不能只看原始码。

事件帧同样保留 12 个字段：I0=990 开始（I1=版本2）；991 为阶段参数，依次为
阶段标识、等待us、SPIHz、SysTick中断是否关闭、TIM14中断是否关闭、目标周期us、
SPI初始化状态、通道预热状态、三个0；992 表示切换到 IN1；999 表示完成。
阶段8的交替周期以实际数据时间戳为准。数据共 1920 行，不含事件和恢复后的正常输出。

烧录后先打开 115200、8N1、FireWater 接收并开始保存，再复位，保持输入稳定，
等待 I0=999 或正常传感器输出恢复后保存 CSV 即可，无需发送任何测试命令。
如需另测一个通道，完成后可发送 `adcdiag 0`～`adcdiag 3`，仅测试指定通道。

此次驱动同时修正了原来的循环“微秒延时”和关中断时依赖 HAL 滴答超时的问题。
所以新基准与上一版绝对采样间隔不同；若新基准不再出现尖峰，只能说明这一组软件时序
修改有影响，仍需进一步拆分验证，不能单凭一次结果认定物理干扰源。

链接器静态调用图发现正常采集/格式化再处理命令的调用链超过原来的 1 KB 栈预算，
启动文件改为 2 KB 栈，给 UART 中断嵌套留余量。这是内存配置缺陷，但尚无证据证明
它是此前 ADC 周期尖峰的原因。

## 上板验证步骤

1. 测量 U5 的 VDD/VIO、REF，并确认 MCU 与 ADC 共地，标称值分别为 3 V 和 2.5 V。
2. 上电后确认串口输出 `AD7682 INIT OK`。
3. 先将每个输入接 GND，再接入低于 REF 的已知电压。REF=2.5 V、输入 1.25 V 时，
   原始码应约为 32768。逐路接入以确认通道顺序，输入电压不得超过 REF。
4. 使用 `log interval 1` 和 `log dump` 检查历史记录中的 ADC 顺序和数值。
5. SPI 主机事务完成不能证明 SDO 连通；SDO 断开时也可能返回合法范围内的码值。
   诊断状态只反映 MCU SPI 事务状态，不是模拟输入/接线自检。
6. 使用逻辑分析仪检查 CNV、SCK、DIN、SDO：每次转换 16 个时钟、模式 0、每轮扫描
   每通道 2 次丢弃转换加 5 次有效转换。

当前默认关闭 CFG 回读（RB=1），因此每次事务只产生 16 个 SCK。若后续需要诊断 CFG
数据链路，可改用 RB=0 并同步把事务扩展为 30 个 SCK；CFG 回读不是芯片 ID，也不是
模拟输入自检，不能单独证明 REF 精度、模拟电源完整性、输入接线或抗干扰性能。
