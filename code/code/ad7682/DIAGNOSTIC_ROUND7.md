# 自动 GPIO 边沿速度诊断（第 7 版）

本轮只执行 GPIO 速度对照，跳过前版阶段 0～28。上电自动先测 IN2，
再测 IN1。保持接线不变，在复位前开启 FireWater CSV 录制，录约4分钟，
包含999后的正常数据，无需发送命令。

每通道11阶段，每阶段3段，每段96组，每组5个原始转换结果。
每个条件合计1440个原始点，两通道合计6336条原始数据行。
分段发送期间不采样；每段先输出995配置事件，捕获完输出996恢复事件，
再输出96条缓存数据。每段的阶段内时间重新从0计时，分析不能直接跨段
拼接I1时间戳。即使990丢失，也可按995、996及I1回退分段。

所有条件固定为MCU 64 MHz、SPI 2 MHz、CNV拉低后等待500 us、每20 ms
采一组。SysTick和TIM14中断保持开启，TIM3正常ADC采样中断停止。
两个气压计始终保持原有工作配置，捕获期间不读取其他传感器、不访问
Flash、不发送UART。每段配置及预热后等待250 ms，再开始采集。

沿用已核对的AD7682引脚：PA1=SCK，PA7=DIN，PA5=CNV，PA6=SDO。
只修改GPIOA OSPEEDR中PA1、PA7、PA5三个两位字段，不改变MODER、
AFR、输出电平或SPI分频。STM32G0 HAL的LOW=0、HIGH=2。
PA6是MCU的接收端，输出驱动速度不控制ADC输出边沿，所以不修改PA6。

重要限制：驱动在通道配置完成后向DIN发送0，捕获阶段MOSI通常保持
低电平。因此MOSI单独升速主要检查其驱动设置和配置阶段影响，不能
当作“MOSI持续跳变时的抗干扰”测试。本轮也不人为增加DIN跳变，以免
同时改变另一个变量。OSPEEDR读回只能确认配置，不能测量实际上升时间。

## FireWater字段

仍为 `ADC:` 前缀，每行12个数值。数据行与前版一致：
I0=通道×100+阶段；I1=本段首点CNV时间us；I2～I6=5个原始码；
I7～I10=后4点相对首点的CNV时间us；I11=状态。

- 990：I1版本7，I2阶段数11，I3每段96组，I4组周期20000 us，
  I5/I6自动测试通道2/1，I7起始阶段29，I8每阶段3段，余下为0。
  手动adcdiag模式I5为指定通道，I6为0。
- 991：沿用前版的等待、SPI频率、中断、初始化和时钟元数据。
- 995：I1阶段标识，I2当前段号1～3，I3总段数3，
  I4请求HIGH掩码（1=SCK、2=MOSI、4=CNV，可组合），
  I5/I6/I7分别为实际读回的SCK/MOSI/CNV速度字段，
  I8实际HCLK Hz，I9 SPI Hz，I10组周期us，I11速度配置状态。
  速度字段0=LOW，2=HIGH，配置状态0=匹配。
- 996：I1阶段标识，I2段号，I3恢复LOW状态（0正常），
  I4/I5/I6分别为恢复后的SCK/MOSI/CNV字段（均应为0），
  I7实际HCLK Hz，I8～I11为0。
- 992：从IN2切换到IN1。
- 999：全部测试完成，I1最终HCLK Hz应为64000000。

数据行I11沿用通信/调度状态；新增4096表示GPIO速度设置或恢复读回
失败，该段不能参与速度对照。每段结束先恢复三个引脚LOW再发送数据。
旧轮次的气压计和PLL对照不会在本轮执行。

## 自动恢复与判读

结束后保持三个引脚LOW，恢复四路每路100 Hz、100点时间中值＋25点
滑动平均。重新填满窗口后使用，保留小数计算和串口两位小数，W25Q128
按原设定间隔优先保存带0.01码精度的滤波结果。诊断原始码不写入正常
历史记录。测试期间暂停正常记录，完成后重新计时。
诊断和滤波继续共用RAM，切换时清空滤波状态与待写标志。

主要比较130与129/131、134与133/135，最后看138与137/139；各自三段
均应表现一致才有较强证据。尖峰次数受采样相位影响，不能仅凭一段
6点变12点就认定噪声翻倍，还应结合幅度、基线散布、连续异常点数和
实际时间戳。GPIO变更若有效，支持数字边沿/驱动条件参与了测量或通信
问题，仍需区分模拟耦合和数字读数错误。
