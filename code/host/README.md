# AD7682 上位机 v1.1

支持 Windows 串口实时接收、CRC-16/MODBUS 校验、单次自动重发、Flash 按时间段导出及 VOFA 格式 CSV。安装包里的 EXE 可直接运行，无需安装 Python。

## 开始使用

1. 先用 Keil / ST-Link 烧录同目录的 `AD7682_crc.hex`，这是配套协议固件。烧录前按平常的方式保存设备参数；不要额外执行全片擦除或 `log clear`，外部 Flash 里的测量记录无需清空。
2. 关闭占用串口的 VOFA+，打开 `AD7682Host.exe`，选择 CH343 对应的 COM 口，再点击连接。默认 **921600、8 数据位、Even 偶校验、1 停止位**。程序自动发送真实 CRLF。
3. 显示“CRC 可靠连接已建立”后才代表双向握手成功。如果超时，检查固件、串口设置和电脑 TX → MCU RX 通路；此前收不到指令的问题仍需实物确认，不能仅凭电脑看到 MCU 数据判断双向正常。
4. Flash 导出选择“ADC 数值”或“压强 hPa”、先旧后新或先新后旧；可勾选时间范围，通过“日历”选择日期，时、分、秒可直接输入，或用上下键、鼠标滚轮调节。每次启动默认为电脑当天零点到启动时刻，可点击“今天 00:00 → 现在”刷新。时间段按 MCU RTC 对应的本地时间筛选，包含两个端点。点击“导出历史 CSV”选择文件位置。
5. 收到经过 CRC 校验的完成帧、核对记录数且 Flash 读取错误数为零后，程序才生成最终 CSV。导出结束停留在设置模式，可点击“实时采集 / 新建记录”恢复实时输出；导出过程中设备继续采样、记录。

`DEMO` 是纯软件演示，包含 1000 条模拟历史记录并故意损坏部分首发帧。它不访问真实硬件，也不执行实际的时间范围筛选。可先用它查看界面、CSV 和自动重发过程。

## 设备设置

连接成功后，切换到“设备设置”页：

- **清空 Flash 日志**：确认后发送 `log clear`，等待 MCU 返回成功并刷新 Flash 状态。此操作无法恢复设备中的历史记录，电脑上已经保存的 CSV 不受影响。如果设备记录开启，清空后会继续产生新记录，因此稍后读取的条数可能大于零。
- **记录间隔**：输入 0.5～86400 秒，必须为 0.5 秒的整数倍，例如 0.5、1、2.5、60；点击“保存间隔”。改变的是 Flash 写入记录的间隔，ADC 采样频率不变。上位机核对 MCU 回读的间隔后才显示成功。
- **历史输出顺序**：选择从旧到新或从新到旧，点击“保存顺序”，会写入设备设置并核对回读。与历史导出页共用选择；执行历史导出时也会将所选顺序发给设备。
- **校准日期时间**：按 `YYYY-MM-DD HH:MM:SS` 输入 2000～2099 年内的有效时间，点击“写入日期时间”；或点击“同步电脑时间”，以发送命令时的电脑本地时间校准 MCU RTC。校准会影响后续记录的时间戳，不会改写已有历史。上位机检查 MCU 回读时间及 RTC 电压低标志后显示结果；串口操作存在延迟，不用于高精度授时。

点击“查看 Flash 状态”可把当前记录数、容量、间隔、顺序和记录开关读回界面。设备设置期间暂停实时串口输出，完成后恢复原有实时/历史模式；导出完成后上位机会自动退出 MCU 设置模式、切换到新的实时记录文件，原来的历史文件保持关闭，连接可以继续使用，不需要重启上位机。断开按钮会等待旧串口线程真正释放后才允许重新连接。导出期间不能执行设备设置。清空、校时等命令响应超时时，上位机不会自动重发，结果显示为未知，需重连核实。

v1.1 只更新上位机，使用已有的配套 CRC 固件即可；本次无需再次烧录。演示模式也支持这些设置，清空只清除模拟记录。

## CSV 格式

历史数据与现有 VOFA CSV 相同：ASCII、CRLF、英文逗号、无 BOM，表头严格为 `I0,I1,...,I14`，每个值保留三位小数。先按 VOFA 的 float32 转换，再格式化，如 MCU 的 `41771.30` 保存为 `41771.301`。

| 列 | 内容 |
|---|---|
| I0～I5 | 年、月、日、时、分、秒 |
| I6～I9 | 温度 °C、相对湿度 %、U7 压强 hPa、U11 压强 hPa |
| I10～I13 | 四路 ADC 数值；选 hPa 时为四路换算压强 |
| I14 | 电池电压 V |

ADC 数值是 Flash 中保存的**经过滤波的 ADC 码值**。hPa 换算为 `ADC × 5 / 65536 × 250 + 225`，依据厂家 35～135 kPa 表格。

实时输出遵循固件现有 18 列格式，表头为 I0～I17，依次为：电池电压、温度、湿度、U7 压强、U7 温度、U11 压强、U11 温度、四路滤波 ADC、三路平均压强、四路原始 ADC。实时与历史文件独立，不混入同一个 CSV。不会加 CRC、序号、电脑时间列，也不会按秒去重。

“另存当前数据 CSV”保存当前记录截至点击处理时的快照。历史尚在传输时保存的快照只是部分数据，不能当成完整导出。

## 可靠传输和恢复

- UART 偶校验继续保留；应用协议额外使用 CRC-16/MODBUS、随机会话号、递增序号和 ACK/NACK。
- MCU 缓存当前一帧，电脑检查 CRC 和数据内容、写入接收文件后发送带 CRC 的 ACK。错帧发送 NACK；MCU 最多重发一次。ACK 丢失时 MCU 等待 500 ms 后也最多重发一次。
- 重复帧只补发 ACK，不重复写 CSV。CRC 验证前不信任序号。序号缺口、再次失败、断线或磁盘错误会中止传输，不生成“完成”的历史文件。
- CRC 保护采样行及历史完成帧；握手、设置、进度等文本命令不在采样帧协议中。命令没有得到预期响应会超时停止，不自动假定成功。
- 传输采用逐帧确认，因此实时串口输出可能降速；传感器采样和 Flash 记录继续按固件调度运行。它不是保持所有实时输出频率的高速缓存方案。
- 实时自动恢复文件位于 `%LOCALAPPDATA%\AD7682Host\captures`。历史临时文件位于选定 CSV 的同一目录，名称为 `目标名.csv.随机号.part`。错误或退出时保留已接收部分，可复制并改名为 CSV 后分析；不会自动续传。
- 磁盘写入先 flush 再 ACK，完成/断开会 fsync；这不等于断电下每条记录都有持久化保证。
- ADC 诊断命令 `adcdiag` / `adcprobe` 在 CRC 模式禁止执行；普通 VOFA 纯文本模式在重新上电或 `link crc off` 后仍可使用。

## 源码与验证

需要 Python 3.11+（含 tkinter）：

```powershell
python -m pip install -r code/host/requirements.txt
python code/host/app.py
python code/host/app.py --demo
python -m unittest discover -s code/host -p test_host.py -v
python code/host/verify_firmware.py
```

最后一项为开发者检查：需要 Keil ARMCC、pyelftools、Unicorn，在 Cortex-M0 仿真器上执行实际 `uart_crc.c`。Keil 工程已加入该源文件和头文件路径。

打包：

```powershell
python -m PyInstaller --noconfirm --clean --windowed --onefile --name AD7682Host --distpath output/AD7682Host --workpath tmp/host-build --specpath tmp code/host/app.py
```

18 项软件测试已通过，覆盖模拟传输、错帧重发、重复帧去重、CSV 字节格式、文件未完成保护、设备设置回读、清空后导出、校时和清空响应丢失时不重复执行。此前实际 MCU CRC 模块的 Cortex-M0 仿真也已通过。新版 EXE 已通过启动检查。**尚未进行本板实际串口收发、设备设置、Flash 导出及长时间采集验证。**
