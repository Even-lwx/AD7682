# AD7682 上位机 v1.4（流式 CRC32 整批导出）

开发环境、虚拟环境安装、测试和 EXE 打包流程见 [上位机开发文档](DEVELOPMENT.md)。

## 源码在哪里

源码完整目录：`D:\lwx\lwx-project\AD7682\code\host\`，界面启动入口为 `app.py`。

在 AD7682 工程根目录运行 `python code/host/app.py`；演示运行加 `--demo`。首次使用按开发文档安装依赖。`device.py` 负责串口与设备交互，`protocol.py` 负责校验、接收与 CSV，`datetime_picker.py` 负责日期时间控件。

已打包 EXE 位于工程内 `output/releases/` 的各版本目录；修改源码后需要重新打包，已有 EXE 不会自动变化。

支持 Windows 串口实时接收、CRC-16/MODBUS 校验、单次自动重发、Flash 按时间段导出及 VOFA 格式 CSV。安装包里的 EXE 可直接运行，无需安装 Python。

## 开始使用

1. 先用 Keil / ST-Link 烧录同目录的 `AD7682_crc.hex`，这是配套协议固件。烧录前按平常的方式保存设备参数；不要额外执行全片擦除或 `log clear`，外部 Flash 里的测量记录无需清空。
2. 关闭占用串口的 VOFA+，打开 `AD7682Host.exe`，选择 CH343 对应的 COM 口，再点击连接。默认 **921600、8 数据位、Even 偶校验、1 停止位**。程序自动发送真实 CRLF。
3. 显示“CRC 可靠连接已建立”后才代表双向握手成功。如果超时，检查固件、串口设置和电脑 TX → MCU RX 通路；此前收不到指令的问题仍需实物确认，不能仅凭电脑看到 MCU 数据判断双向正常。
4. Flash 导出选择“ADC 数值”或“压强 hPa”、先旧后新或先新后旧；可勾选时间范围，通过“日历”选择日期，时、分、秒可直接输入，或用上下键、鼠标滚轮调节。每次启动默认为电脑当天零点到启动时刻，可点击“今天 00:00 → 现在”刷新。时间段按 MCU RTC 对应的本地时间筛选，包含两个端点。点击“导出历史 CSV”选择文件位置。
5. 收到经过 CRC 校验的完成帧、核对记录数且 Flash 读取错误数为零后，程序才生成最终 CSV。导出结束自动恢复实时接收。

## v1.4 流式分组校验

**烧录本包最新 `AD7682_crc.hex` 并运行本包 EXE，才能启用。** 导出页新增“整批校验条数”，默认 100，可选择 1000。旧固件会回退到 16 条窗口或逐条确认，通信日志显示实际协商模式。

- 批内直接发送 `samples:` 文本行，去掉每条串口会话号、序号、长度和 CRC 尾；整批末尾发送一次 CRC32 和实际行数。批次起止控制帧仍用原 CRC16 保护，会话和序号保护批次顺序。
- CRC32/ISO-HDLC 使用标准参数：反射多项式 EDB88320、初值 FFFFFFFF、最终异或 FFFFFFFF；覆盖每条原始 ASCII 数据行（不含 CRLF）及一个规范 LF。标准向量 `123456789` = CBF43926。
- MCU 边从 Flash 读、边发送、边增量更新一个 32 位 CRC，不缓存整批。CRC32 采用 16 项只读半字节表（64 字节 Flash，每字节两次查表）；短控制帧 CRC16 也改为只读查表。相对 v1.3 总静态 RAM 占用不增加。
- 批次边界按最多扫描 100/1000 条 Flash 记录确定；时间筛选或 Flash 读取错误会让实际输出行数更少，可能为空。电脑最多暂存所选批次的数据，在 CRC32、行数、批次顺序和内容校验全部通过后才写 CSV、flush 并回 ACK。
- 坏批次不写入最终记录；MCU 按 Flash 检查点重读整批一次。ACK 超时从批尾发送后计时 500 ms，超时也整批重放一次。ACK 丢失引起的重复批次只补 ACK，不重复写入。仍失败则中止并恢复采样。
- 1000 条减少批次确认次数，但会增加一次错误的重传量、校验前的等待和电脑暂存量；不保证一定比 100 条更快。确认链路稳定后可比较界面条/秒。
- 增量 CRC 仍需处理每个数据字节，“每批一次校验”减少的是帧封装与确认次数，不是只对整批执行一次算术运算。查表减少计算开销；串口线速、Flash 读取和浮点转文本仍是限制。
- Flash 本身每条存储记录的 CRC16 校验继续保留，用来检测存储损坏；与串口整批 CRC32 是两层校验。
- 沿用 v1.3 独占导出：导出时停止传感器采样、新记录写入，完成/失败/取消自动恢复，导出期间有真实的采样时间空档。CSV 表头、列顺序与三位小数规则保持不变。

## 导出调度

导出由主循环读取 Flash 并阻塞发送 UART，不使用发送定时器。TIM3 平时负责 100 Hz ADC 采样，TIM14 负责毫秒调度；导出时暂停这两项采样调度和新日志写入，保留 SysTick、UART 中断与 RX DMA。主循环连续处理导出、命令、ACK/NACK 和超时。

开始前提交已有待写快照，再固定导出序号范围。完成、失败、取消或重新握手后自动恢复调度，清除积压请求并重建滤波窗口，不补写导出期间的旧测量值。第一条新记录需等待新数据就绪，RTC 继续走时。

串口 921600 / 8E1 的理论上限约为 83.8 KB/s；实际速度还受 Flash SPI、浮点格式化、确认、USB 驱动及存盘影响。旧固件兼容模式为 16 条窗口或逐帧确认，界面日志显示协商结果。

`DEMO` 是纯软件演示，包含 1000 条模拟历史记录并故意损坏部分首发帧。它不访问真实硬件，也不执行实际的时间范围筛选。可先用它查看界面、CSV 和自动重发过程。

## 设备设置

连接成功后，切换到“设备设置”页：

- **清空 Flash 日志**：确认后发送 `log clear`，等待 MCU 返回成功并刷新 Flash 状态。此操作无法恢复设备中的历史记录，电脑上已经保存的 CSV 不受影响。如果设备记录开启，清空后会继续产生新记录，因此稍后读取的条数可能大于零。
- **记录间隔**：输入 0.5～86400 秒，必须为 0.5 秒的整数倍，例如 0.5、1、2.5、60；点击“保存间隔”。改变的是 Flash 写入记录的间隔，ADC 采样频率不变。上位机核对 MCU 回读的间隔后才显示成功。
- **历史输出顺序**：选择从旧到新或从新到旧，点击“保存顺序”，会写入设备设置并核对回读。与历史导出页共用选择；执行历史导出时也会将所选顺序发给设备。
- **校准日期时间**：按 `YYYY-MM-DD HH:MM:SS` 输入 2000～2099 年内的有效时间，点击“写入日期时间”；或点击“同步电脑时间”，以发送命令时的电脑本地时间校准 MCU RTC。校准会影响后续记录的时间戳，不会改写已有历史。上位机检查 MCU 回读时间及 RTC 电压低标志后显示结果；串口操作存在延迟，不用于高精度授时。

点击“查看 Flash 状态”可把当前记录数、容量、间隔、顺序和记录开关读回界面。设备设置期间暂停实时串口输出，完成后恢复原有实时/历史模式；导出完成后恢复采样、退出 MCU 设置模式并切换到新的实时记录文件，原来的历史文件保持关闭，连接可以继续使用。断开按钮会等待旧串口线程真正释放后才允许重新连接。导出期间不能执行设备设置。清空、校时等命令响应超时时，上位机不会自动重发，结果显示为未知，需重连核实。

设备设置兼容原 CRC 固件；本版的整批 CRC32 功能需要配套新固件。演示模式也支持这些设置，清空只清除模拟记录。

## CSV 格式

历史数据与现有 VOFA CSV 相同：ASCII、CRLF、英文逗号、无 BOM，表头严格为 `I0,I1,...,I14`，每个值保留三位小数。先按 VOFA 的 float32 转换，再格式化，如 MCU 的 `41771.30` 保存为 `41771.301`。

| 列 | 内容 |
|---|---|
| I0～I5 | 年、月、日、时、分、秒 |
| I6～I9 | 温度 °C、相对湿度 %、U7 压强 hPa、U11 压强 hPa |
| I10～I13 | 四路 ADC 数值；选 hPa 时为四路换算压强 |
| I14 | 电池电压 V |

ADC 数值是 Flash 中保存的**经过滤波的 ADC 码值**。hPa 换算为 `ADC × 5 / 65536 × 250 + 225`，依据厂家 35～135 kPa 表格。

实时输出遵循固件现有 18 列格式，表头为 I0～I17，依次为：电池电压、温度、湿度、U7 压强、U7 温度、U11 压强、U11 温度、四路滤波 ADC、三路平均压强、四路原始 ADC。实时与历史文件独立，不混入同一个 CSV。不会加 CRC、序号、电脑时间列，也不会按秒去重。

“另存当前数据 CSV”保存当前记录截至点击处理时的快照。历史尚在传输时保存的快照只是部分数据，不能当成完整导出。

## 可靠传输和恢复

- UART 偶校验继续保留；应用协议额外使用 CRC-16/MODBUS、随机会话号、递增序号和 ACK/NACK。
- MCU 缓存当前一帧，电脑检查 CRC 和数据内容、写入接收文件后发送带 CRC 的 ACK。错帧发送 NACK；MCU 最多重发一次。ACK 丢失时 MCU 等待 500 ms 后也最多重发一次。
- 重复帧只补发 ACK，不重复写 CSV。CRC 验证前不信任序号。序号缺口、再次失败、断线或磁盘错误会中止传输，不生成“完成”的历史文件。
- CRC 保护采样行、窗口起止帧及历史完成帧；握手、设置、进度等文本命令不在采样帧协议中。命令没有得到预期响应会超时停止，不自动假定成功。
- 实时传输采用逐帧确认，因此实时串口输出可能降速；Flash 导出采用批次确认（兼容模式为窗口或逐帧确认）。导出期间暂停 MCU 采样与新记录，结束后自动恢复。
- 实时自动恢复文件位于 `%LOCALAPPDATA%\AD7682Host\captures`。历史临时文件位于选定 CSV 的同一目录，名称为 `目标名.csv.随机号.part`。导出期间串口短暂断开时，上位机会自动关闭旧句柄、重新握手并从本次 Flash 快照重新导出，最多重试 3 次；每次重试会丢弃旧 `.part`，避免重复记录。三次仍失败才保留现场文件并提示用户。
- 磁盘写入先 flush 再 ACK，完成/断开会 fsync；这不等于断电下每条记录都有持久化保证。
- ADC 诊断命令 `adcdiag` / `adcprobe` 在 CRC 模式禁止执行；普通 VOFA 纯文本模式在重新上电或 `link crc off` 后仍可使用。

## 源码与验证

需要 Python 3.11+（含 tkinter）：

```powershell
python -m pip install -r code/host/requirements.txt
python code/host/app.py
python code/host/app.py --demo
python -m unittest discover -s code/host -p "test_*.py" -v
python code/host/verify_firmware.py
python code/host/verify_dump.py
python code/host/verify_exclusive.py
```

最后三项为开发者检查：需要 Keil ARMCC、pyelftools、Unicorn，在 Cortex-M0 仿真器上执行实际 CRC 模块、提取的 Flash 导出函数以及暂停/恢复函数。Keil 工程已加入该源文件和头文件路径。

打包：

```powershell
python -m PyInstaller --noconfirm --windowed --onefile --name AD7682Host --distpath output/releases/AD7682Host-v1.4 --workpath tmp/host-build --specpath tmp code/host/app.py
```

实际导出条/秒以连接设备后的界面为准；软件仿真不代替实板测速与采样恢复检查。
